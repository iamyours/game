# 直接发送给 Codex 的提示词

## 十七 可直接发送的开工提示词

### 首次开工
请在当前工程开发风暴弓手。先读取 AGENTS.md、docs/PRD.md、docs/ARCHITECTURE.md、docs/PLAN.md、docs/STATUS.md 和 tasks/T001.md，检查现有目录、版本、配置与未提交改动。按 T001 实现工程与工具基线，不能只返回计划。

沿用已经确定的横屏实时物理对射。不要添加账号、广告、支付、强化、跳跃或竖屏版本。优先保留用户已有文件，通过实际安装的 Cocos 小版本验证。任务涉及的必要修复在已有范围内继续完成，不逐步询问确认。

结束时给出实际改动、验证命令和退出码、运行入口、未验证项及下一任务，并同步 STATUS.md。环境缺少编辑器或 WebGL 时，把独立代码与静态检查完成，明确运行阻塞和最小解除动作；不要伪造构建或试玩成功。

### 接续下一个任务
读取 AGENTS.md、STATUS.md、PLAN.md 和当前任务卡，从已验证的状态继续。先检查前置任务证据，再完成依赖已通过的下一项。保持改动集中，发现错误先修复，再推进。

当前任务若只达到 CODE_READY，先完成缺失的必要运行验证。任务达到 DONE 时更新任务卡、STATUS.md 和证据索引。不要把仍未执行的真机测试写成通过。

### 进入物理试验关
按 T002 至 T007 的依赖逐项实现 PhysicsLab。先做 24 米视野、两个弓手和一种普通箭。人物使用 11 刚体及受限关节驱动，箭从真实弓口发射。不要先制作完整菜单与美术。

增加定点命中调试入口和 shotId 日志，证明头、腰、持弓臂、膝的受力不同。保留掉弓、掉盔和坠台的真实物理过程。每完成一项运行相应检查并记录参数，不把整个阶段做成无法复查的一次大改动。

这些提示词与任务文件共同使用；数值和行为的权威位置仍是 PRD、配置与验收文件，提示词不复制所有参数。

## 十八 调试和反馈提示词

### 命中后仍然没有爽感
先不要增加粒子和震屏。用同一 PhysicsLab 场景、相同箭速和普通箭，分别击中头、腰、持弓臂、膝并录制。检查接触点、一次性冲量、局部关节控制权重、恢复时间、身体质量和支撑状态。

说明四类命中目前分别造成什么实际运动，找出反应相同或被强回正抵消的原因。优先修复物理与姿态，保留运行前后录像和参数差异。静态测试通过不代表手感已经通过。

### 飞行太短或像慢动作
记录 13、15、17 米测试的距离、速度、角度和离弦到命中的时间。检查单位转换、世界尺寸、相机比例和重力。根据真实轨迹调整距离与速度，普通中距离射击先以 0.7 至 1.1 秒为目标，不加命中延迟，不只拉长拖尾。

若看不清关节，先恢复人物比例并缩减背景占比，不继续把角色缩小。相机保持全景，不逐箭跟随；报告画面可读性和飞行期待之间的具体取舍。

### 修复穿透或重复扣血
先复现并保留 shotId、stepId、接触部位和候选路径。检查 Bullet、固定步、箭尖扫掠、路径排序和 resolved 标记。新增能暴露这次问题的规则或运行回归，不能只把箭碰撞体放大到明显偏离视觉。

### 评审一个里程碑
对照当前任务卡与 ACCEPTANCE.md 审查实现。列出能导致玩法错误、物理不稳定、输入残留或渠道失败的问题，给出具体文件和触发条件。核对测试是否真实执行，以及录屏是否对应当前源码与配置。

可以直接修复已授权范围内的问题。需要产品判断的手感取舍，用一段可复现演示和少量参数对比说明；不要在没有运行证据时仅凭“结构合理”放行。

### 反馈模板
场景与版本；设备；实际操作；期望结果；实际结果；录像位置；复现次数；允许优先调整的参数。问题描述尽量使用“打膝盖后腿没有弯、整身只平移”等可观察行为。
