# 验证证据（精简仓库）

本目录已有真实 Creator / WebGL 运行记录，也有离线检查和失败记录。它不参与游戏运行，不需要随游戏发布；记录存在不代表验收通过，结论以对应报告的版本、命令、退出码和范围为准。

## 仓库保留什么

- Markdown 验证摘要：运行场景、源码/配置版本、命令退出码、结论与阻塞。
- JSON 结构化结果与哈希清单：包含失败样本，不因失败而删除。
- `.sha256` 指纹，以及 `.gitignore` 中显式列出的少量关键截图。
- 当前关键入口：`zip-merge-20261114/verification.md`（当前包基础烟测）、`latest-pull-20261113/verification.md`（历史完整回归失败）、`expedition-20261113/verification.md`（离线功能范围）。

## 原始文件的本地归档

重复构建/测试日志、批量布局及离线截图、录像、临时执行脚本、PID/服务进程状态不再被 Git 跟踪。原文件仍留在本机原路径，并由 `.gitignore` 忽略，没有物理删除。

首次清理前的完整副本保存于工程同级的 `game-evidence-archive-20261114-005522.zip`。归档 SHA-256、来源提交、移出文件的相对路径/大小/哈希见 `ARCHIVE_INDEX.json`。不要把此归档重新提交到仓库。

**历史报告中提及但当前检出没有的原始路径，并非新的缺失或测试未执行：**先在 `ARCHIVE_INDEX.json` 查询；本机可直接读原路径，换机后从上述归档取回。无法取得本地归档时，可按索引中的 `sourceCommit` 从已有 Git 历史读取，例如：

```sh
git show f372b06:evidence/zip-merge-20261114/build.log
# 或从历史提交恢复单个文件到任意本地路径，不改当前索引：
git show f372b06:evidence/zip-merge-20261114/build.log > /tmp/storm-archer-build.log
```

原始证据没有被改写或重新解释。历史销毁/关节失败、G1 与真机阻塞仍有效。本次仅精简当前检出的文件；**没有重写 Git 历史，已存在的历史对象不会因此缩小**。

## 后续记录规则

1. 按任务/版本建目录，先写 `verification.md`，保留命令退出码、版本指纹和失败结论。
2. 原始输出照常写入本地 `evidence`；默认不入 Git。确需保留关键截图时，在 `.gitignore` 明确加入单文件白名单；不使用 `git add -f` 批量绕过规则。
3. 摘要若引用本地原件，注明“仅本地/外部归档”，并记录哈希及可取回位置；不要只写“已测试”。
4. 不提交凭据、私人文件、服务 PID、临时机器状态或大录像。可复用测试脚本放 `scripts/`，不要放在证据目录。
5. 仓库约束由 `tests/evidence-policy.test.mjs` 回归；不得把离线图、纯逻辑测试或基础烟测当作完整物理/G1/渠道通过。
