# 验证方式与用例

## 十九 自动化检查与运行验证

### 自动化要验证真实风险
纯逻辑测试覆盖伤害与装甲余伤、一次命中去重、冷却与体力、多触点状态、死亡取消攻击、存档迁移和重复结算。配置校验覆盖箭种引用、关卡解锁、平台尺寸、敌人上限与数值范围。

测试不能只检查函数存在或逐字复制实现。物理关节、扫掠与移动肢体的交互，需要在引擎运行中检查。可加入引擎内断言和场景测试，但不能用假的刚体对象代替所有物理验收。

| 检查层 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| 配置校验 | 格式 引用 范围 | 实际能否打中移动角色 |
| 纯逻辑测试 | 规则边界与状态转换 | 关节稳定和碰撞求解 |
| 类型与构建 | 接口和工程可以处理 | 操作好用或手感舒服 |
| 引擎场景 | 实际物理与输入表现 | 手机宿主行为完全一致 |
| 真机与试玩 | 目标渠道操作与手感 | 所有设备永久无问题 |

### 证据记录规范
每条用例记录 caseId、sourceRevision、configHash、engineVersion、平台、设备、步骤、结果和证据路径。无 Git 提交时记录 dirty 状态与源码快照标识，不编造提交号。QA 结果仅使用 NOT_RUN、PASS、FAIL、BLOCKED 和 NOT_APPLICABLE。

NOT_APPLICABLE 仅用于当前明确延期的渠道或功能，并说明决策。未执行不能算不适用。自动检查日志与运行录像分开保留，记录时间与构建版本。

### 基本回归矩阵
16 比 9 和超宽横屏；触摸和鼠标；低帧率与恢复；左右骨架；站立和倒地；身体、装甲和地形；普通、冲击和穿甲；暂停、失败、重开与切后台。每次只重跑受影响用例，里程碑放行再跑必要完整矩阵。

固定随机种子便于对照，但不承诺不同设备或物理后端逐帧完全一致。跨平台验收看规则和可接受误差，不依赖浮点状态逐位相同。
