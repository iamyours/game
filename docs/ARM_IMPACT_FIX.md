# 手臂交叉与箭种冲击修复

2026-11-08；初始拉取基线 main `2c8290f7725a942585291601ace973f11642a75f`；开发期间远端新增 `db9cb2f64c909b820023eec804875ab5f816b79b`，已再拉取并合入其 Creator 编译/资源 meta 修复，本轮以 db9cb2f 为提交基线。用户现象为手臂关节直角交叉、箭型冲击没有区别。以下是源码定位和候选修复，尚未在 Creator 中复验画面。

## 手臂

原皮肤直接放在每个刚体中心、角度为零、宽高取刚体包围盒。可是右上臂的肩肘局部锚点差为 (0.32,-0.17) 米，右前臂的肘握点差为 (0.23,-0.14) 米，均不是贴图竖直长轴。IK 虽然连接了物理关节，画出的肉身却没有沿关节连线，容易形成偏转、交叉和脱节观感。

`armVisualLayout` 根据实际肩/肘/握点计算局部中点、长度与方向，Sprite 子节点从竖直长轴旋转到连线方向，并用少量端帽重叠遮住关节缝。灰盒 fallback 同样沿这些端点绘制。没有写动态刚体变换，没有改关节、碰撞盒尺寸、质量和世界单位。碰撞盒仍沿用原骨架，图形与接触区域也必须在引擎里复核，不能把此修复等同于碰撞重标定完成。

此外旧持弓目标距肩仅 0.42 m，相对两段总长约 0.63 m，本就求出约直角弯肘。改为 0.60 m，保留弯曲但更接近伸展。为了后侧拉弦手在全角度仍可达，同步把弦静置深度从 0.36 调为 0.55 m，拉弦行程仍 0.20 m；已用实际骨架测试 -15°～75°、五档拉距下两手可达。角色持弓范围改变，站台稳定性与三姿态实射需重新验收。

## 箭种冲击

旧实现已有普通/冲击/穿甲的 1.8/3.2/1.4 N·s，但任何非致命命中都立即切同一个 staggered 目标姿态，关节马达仍按统一控制强度工作。这样既用相同目标姿态主导反馈，又快速抵消局部旋转。死亡则只切 downed，主动驱动仍未关闭。

本轮保留原箭速、伤害、冲量及命中点单次施力，增加可配置、按部位与箭型区分的关节控制权重：

| 满弓敌人受击 | 配置冲量 N·s | 局部控制权重 | 邻接控制权重 | 局部/邻接恢复秒 |
| --- | --- | --- | --- | --- |
| 普通 | 1.8 | 0.25 | 0.75 | 0.28 / 0.18 |
| 冲击 | 3.2 | 0.03 | 0.20 | 0.75 / 0.50 |
| 穿甲 | 1.4 | 0.45 | 0.90 | 0.18 / 0.12 |

这些是未标定的首轮参数，不是实际手感结论。冲击更强、更长时间放松支撑；穿甲主要保留破甲区别，不做额外整身击退。

- 头命中先降 neck、邻接 waist；胸腰降 waist/支撑关节；手臂只降该侧肩肘及邻接腰；腿只降该侧髋膝及邻接腰。
- 保留真实弓臂 IK 目标，用有限马达扭矩乘受击权重；站立胸部平衡也乘 waist 权重。没有播放统一后仰或强制旋转身体。
- 权重随固定步线性恢复；弱后续命中不会把强冲击立即恢复为满控制。每关节一个有界包络，重置清空。
- 轻拉和玩家冲量上限仍有效：降权按实际施加冲量相对种子满弓冲量缩放；玩家手臂保留最低 0.35 控制、0.25–0.45 秒恢复。
- hp 归零立即把所有主动关节最大扭矩归零，停止平衡和 IK，重置后恢复正常；活体倒地不当作死亡。
- lastHit 记录本箭实际 impulseNs 和 jointReaction；靶场显示实际冲量，避免只看箭的颜色判断配置是否走通。

## 本机复验

```sh
npm ci --ignore-scripts
# Creator 3.8.8 打开根目录，导入新 reaction.ts 并保存自动生成的 meta
npm run typecheck:engine
npm run build:web
python3 -m http.server 7458 --bind 127.0.0.1 --directory build/web-desktop
# 另一个终端
npm run test:web:arm-impact
npm run test:web:t004
```

`test:web:arm-impact` 使用真实 Box2D，对同一部位同一接触点注入 after-step 命中快照，分别记录三箭的即时 Δv、关节权重与后续身体位置，检查 Δv×质量与单次冲量吻合、图片端点与真实锚点对齐、死亡驱动归零。它隔离反应链路，不验证箭碰撞，也不替代实射、录像或主观手感。

手动在同力度、同部位、每次重置后比较三箭，录制头/胸腰/持弓臂/膝四组，先看无粒子身体反应，再测试站立/后仰/倒地瞄准和30秒静置/20次重置。若仍有穿身、关节不稳、冲击不明显，保留 snapshot、录屏及新配置哈希继续调，不以更大伤害或粒子掩盖。
