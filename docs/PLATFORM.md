# 渠道与性能

## 二十一 性能预算与降级

### 在目标设备测量
首轮目标为主流设备接近 60 帧，低配档稳定 30 帧。T014 必须记录具体设备型号、系统和宿主版本，再报告帧时分布；这些是待验证目标，不是当前已经达到的数据。

| 预算项 | 首轮限制 |
| --- | --- |
| 活敌人 | 普通波最多 2 名 首领单独一波 |
| 飞行箭 | 全场最多 24 支 由射击系统限额 |
| 插箭视觉 | 全场最多 24 支 每角色最多 6 支 |
| 尸体 | 最多 2 具 默认 3 秒回收 |
| 物理掉落物 | 同时最多 6 件 超限回收最旧件 |
| 刚体 | 常态目标不超过 80 峰值预算 110 |

刚体预算包括人物、弓盔、平台、箭和补给。实际工厂实现若超过预算，需要先给出计数证据并调整生成或回收规则，不只修改报表阈值。

### 固定步与卡顿
物理步长先用 1 除以 60 秒，位置与速度迭代先各 8 次。不要同时启用引擎固定步和另一套重复 step。最大补步行为以小版本公开接口确认，卡顿恢复后不无限追赶时间；暂停和后台恢复直接重置时间基准。[C3]

### 降级顺序
先减少粒子、拖尾采样、背景视差和动态光；再缩短装饰掉落物与尸体保留时间。降级不改变命中部位、装甲结算和箭速，不通过降低物理更新频率牺牲碰撞可靠性。低配视觉策略与基础战斗规则分开配置。

### 稳定性
连续战斗至少 15 分钟，重开至少 30 次，观察刚体、关节、监听器和内存是否持续增长。内存允许垃圾回收波动，重点查反复重开后的单调上升。保留采样日志；出现泄漏先修对象池和生命周期，不以更低敌人数掩盖问题。

## 二十二 渠道开发与发布边界

### 同一套战斗分渠道适配
PlatformAdapter 统一存储、生命周期、音频启动和可选震动接口。战斗系统不直接依赖 wx 或 tap 全局变量。平台不支持的表现能力返回可接受的空实现，核心射击与存档仍须正常。

微信使用小游戏发布路径，构建设置为横屏；安全区、音频解锁、切后台暂停、触摸取消和本地存储都要在宿主真机测。开发者工具运行成功不能替代手机结果。[C6]

### TapTap 的交付形态
TapTap 既有安装包发布，也有即点即玩的小游戏。本版默认以 Android 安装包作为 TapTap 的首条验证路径，复用 Cocos 原生构建。若明确选 TapTap 小游戏，在 T016 开始前记录改走普通小游戏还是 H5 小游戏，按该路径验证转换工具、API 和打包要求。[T2]

本资料包不把 Web 构建直接认定为 TapTap 小游戏包，也不承诺尚未验证的 Creator 小版本存在一键转换能力。T016 的 2 人日为单一路径的适配估算，发现额外引擎移植工作时单独复估。

| 渠道 | 必须保存的验证证据 |
| --- | --- |
| Web | 实际可打开构建 触摸或鼠标 音频与重开 |
| 微信小游戏 | Android 与 iOS 真机 操作 暂停 存档 性能 |
| TapTap Android | APK 安装 启动 横屏 三关与持久化 |
| TapTap 小游戏 | 仅选择该路径时 提交所选宿主预览证据 |

### 构建与上架分开
工程构建、渠道预览和整理审核材料可在开发阶段完成。正式提交审核、开通商业能力或公开发布以用户授权为准。上架时核对当时的账号资质、审核要求与素材规范；本版不把动态审核规则写死在游戏逻辑里。

广告、支付和渠道登录暂缓。以后接入时另开任务，不能在核心原型阶段插入阻断战斗的商业流程。
