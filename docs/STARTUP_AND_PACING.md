# D042 首场加载与战斗衔接

基线：53e3438，Creator 3.8.8。两段用户视频显示：微信启动后经过引擎插屏和黑屏；战斗先出现灰盒，随后补背景、人物与弓箭。另一段显示倒地敌人仍存活时目标状态不清楚。

## 实现

Boot 以最多4项并发执行首场资源的实际 load（含解析），覆盖配置、双方人物图集/切片、遗迹背景/平台、三把弓及箭矢。资源按任务权重显示完成进度，不声称是字节百分比。成功资源保留引用，失败停止派发并等在途任务结束；单项20秒超时，点屏幕重试。退出取消等待并释放引用。

之后组装 PhysicsLab，但保持输入与固定步暂停。等待双方人物、平台、背景和三套武器完成，再在遮罩下绘制两帧，才开放战斗。后续敌人从驻留图集同步挂皮肤，平台从驻留切片同步挂载。音乐在开战后逐个解析，下一场景在游玩期间提前准备；音乐仍等首次触摸解锁。

新增项目构建扩展 `extensions/storm-startup`：Web/微信构建结束后将已有的默认插屏最短时长上限降到500毫秒；保留logo/watermark，已关闭的插屏不重新打开。支持settings.json及MD5文件名，后者重新命名并更新入口引用。微信宿主白色启动页由宿主管理，这个扩展不修改它。Creator打开项目后确认扩展启用，构建日志应出现 `[StormStartup]`；亦可执行 `npm run optimize:startup -- build/wechatgame`。本环境未验证编辑器加载该扩展。裁去未使用的Spine、DragonBones、TiledMap、视频/WebView、粒子、富文本、mask、animation与tween模块，保留现有2D物理后端。

普通敌人持续倒地或失弓3秒后，其真实平台转动态坠落；BOSS单纯倒地不会触发，仅失弓5秒触发。倒计时、裂纹和平台坍落提示均读取固定步。坍落不直接扣血/计分；仍由真实出界或伤害走原死亡去重。玩家倒地控制不变。新增短伤害/爆头数字、击败到下一敌人倒计时、五格阶段进度与距强化的明确数字。既有每5次击败强化、15战BOSS与跨局修炼保留。

## 复验

1. 用Creator3.8.8导入新增StartupLoading.ts并生成meta，确认项目构建扩展启用；构建当前包，确认裁剪后无组件缺失。
2. 微信真机冷启动录屏；慢网/断网/恢复重试，首个可操作画面必须同时含背景、双方完整人物、平台与当前弓箭，加载时不能扣血。测量冷/热启动而非根据进度条估时。
3. 切三弓并实射；连续重开检查引用/监听；退出加载页/后台恢复不应收到迟到操作。
4. 实射打倒/失弓，检查3秒崩台、坠落死亡一次；BOSS仅倒地不崩台，失弓5秒才崩台。检查暂停冻结倒计时和玩家死亡不再推进压力。
5. 实射到第5、15战，检查强化选择、BOSS、换景与音乐。继续15分钟/30次重开和旧关节/销毁回归。

便携生产流程夹具可验证等待顺序、引用、取消和状态规则，不能代替GPU、真实物理或真机启动性能。本轮不关闭历史关节/销毁失败，不放行G1或发布。
